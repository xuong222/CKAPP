# CH32 工业监控上位机使用说明

## 1. 软件用途

本软件用于通过串口和 Modbus-RTU 协议连接 CH32 多传感器融合检测设备，提供工业仪表盘、报警显示、参数读写、原始收发数据、常用指令、手动定时发送、通信日志和专家寄存器工具。

当前版本支持：

- 0x03：读取保持寄存器；
- 0x06：写单个保持寄存器；
- 0x10：写多个保持寄存器；
- 设备私有 0xFE 未知地址查询；
- Windows x64 自包含单文件发布。

本软件不包含趋势曲线，不会在连接后自动轮询，也不会自动恢复上次定时发送状态。

## 2. 安装和启动

发布包的主程序为 `CH32UpperComputer.App.exe`。发布目标是 Windows x64 自包含单文件，设计上不依赖目标电脑预装 .NET Desktop Runtime；正式交付前应使用第 17 节的隔离验证脚本或等效干净虚拟机保存验证证据。

启动步骤：

1. 将 EXE 复制到本地可写目录。
2. 双击运行；首次启动不会自动打开串口。
3. 如果 Windows 显示来源提示，请先核对文件来源和 SHA256，再决定是否运行。
4. 软件设置保存在 `%LOCALAPPDATA%\CH32UpperComputer\settings.json`，内容使用 UTF-8。

建议系统为 64 位 Windows 10 或 Windows 11，屏幕缩放建议为 100%～150%。

## 3. 主界面说明

主窗口由五个页面和顶部状态区组成：

- 监控：六张数据卡、综合报警、具体报警、紧凑收发框和单列常用指令；
- 参数：读取或保存普通参数组，以及地址、波特率、恢复出厂专用操作；
- 寄存器工具：0x03、0x06、0x10、原始调试和 0xFE 查询；
- 通信日志：查看、筛选、清空和导出通信记录；
- 系统：查看版本、路径、协议范围和免责声明。

六张数据卡依次显示温度、烟雾、PM2.5、CO、CO2 和 SO2。右侧报警区只根据设备返回的 40009、40010 状态显示报警，不会根据测量值自行虚构报警。

## 4. 串口连接

推荐设备参数为：

- 波特率：9600；
- 数据位：8；
- 校验位：None；
- 停止位：One；
- 流控：None；
- 从站地址：1；
- 响应总超时：1000 ms。

操作步骤：

1. 在顶部串口区选择端口和参数。
2. 点击“连接”。
3. 连接成功后状态显示“已连接 · 等待手动指令”。
4. 此时软件只启动唯一后台读取循环，不会发送任何读取或写入帧。

连接后没有线路写入属于设计行为。只有点击发送、常用指令、参数操作或手动开启定时发送后才会产生事务。

## 5. 收发框和手动发送

收发框接受十六进制字符，并允许使用空格、Tab、换行或短横线分隔。字符数量必须组成完整字节。

### 5.1 自动 CRC

- 开启“自动 CRC”时，如果输入末尾没有有效 Modbus CRC，软件自动追加 CRC16；
- 如果输入已经包含有效 CRC，软件不会重复追加；
- 关闭“自动 CRC”时，输入会按原始字节发送，适合专家调试。

软件会先严格识别 0x03、0x06、0x10 和固定 0xFE 请求。识别成功时使用标准事务模式；无法识别的帧使用原始调试模式。

### 5.2 标准事务模式

标准事务根据请求结构计算响应长度，并校验 CRC、地址、功能码、数量和写回显。只有完整匹配的成功 0x03 响应可以更新数据卡和寄存器快照。

### 5.3 原始调试模式

原始调试模式保留收到的原始字节。无法推导结构时，以下任一条件会结束一次捕获：

- 字节间静默超时；
- 总响应超时；
- 4096 字节接收上限。

原始捕获不会更新设备参数或数据卡。

## 6. 常用指令

监控页右侧提供五条单列常用指令：

1. 读取监测数据：40003～40010；
2. 读取全部寄存器：40001～40036；
3. 读取报警参数：40011～40023；
4. 读取补偿参数：40030～40035；
5. 未知地址查询：固定 0xFE 查询。

点击常用指令只会把按当前地址重新生成的帧载入输入框，不会立即发送；仍需用户点击“发送”。

## 7. 定时发送

定时发送默认关闭，连接后也不会自动启动。

启动步骤：

1. 准备并检查当前收发框指令；
2. 设置定时间隔，允许范围为 100～3,600,000 ms；
3. 点击“开启定时”；
4. 软件先等待一个完整间隔，再尝试第一次发送。

定时策略是固定延迟：一次事务完全结束后，才重新等待一个完整间隔。不会积累 tick、不会追赶补发，也没有请求队列。

点击“停止定时”会立即取消下一次调度。已经进入物理写入的单次事务允许完成，但完成后不会安排下一次。断开串口、修改地址、修改波特率、恢复出厂、超时重同步或退出程序都会保持定时发送关闭，必须由用户再次手动开启。

## 8. Busy 背压

同一时刻最多允许一个活动 Modbus 事务。当前事务尚未完成时：

- 发送、常用指令、参数保存和专家操作按钮进入忙状态；
- 快速重复点击不会建立队列；
- 穿透到协调器的第二项请求立即返回 Busy；
- Busy 请求不分配 TransactionId，也不会写串口。

界面提示“当前已有请求等待处理，请完成或取消后再试。”时，请等待当前事务结束或断开连接。

## 9. 参数页面

进入参数页不会自动读取。普通参数分为两个连续组：

- 40011～40023：报警阈值、回差和报警使能；
- 40030～40035：六项补偿参数。

读取操作使用 0x03。保存组参数前，软件先校验组内全部值；任一值非法时整组不发送。全部合法后，整组通过一个 0x10 请求写入，避免部分更新。

40023 可以使用 `0x0000`～`0x003F` 原始掩码，也可以使用六个逐项开关。只允许低六位。

从站地址、波特率和恢复出厂不会混入普通 0x10 参数组，必须使用各自的专用流程。

## 10. 地址、波特率和恢复出厂

### 10.1 修改地址

软件使用旧地址发送 0x06，并验证完整回显。只有收到旧地址下的正确响应后，才更新本地从站地址。允许地址范围为 1～64。

### 10.2 修改波特率

软件在旧波特率下写入 40002，收到正确回显后关闭串口，再按新波特率重新打开。支持代码：

- 0：2400；
- 1：4800；
- 2：9600；
- 3：19200；
- 4：38400；
- 5：57600。

### 10.3 恢复出厂

勾选二次确认后，软件写入 40036=1。成功后本地配置切换到地址 1、9600-8-N-1。40036 读取恒为 0，命令不会作为持久状态保留。

### 10.4 ConfigurationUncertain

地址、波特率或恢复出厂写入可能已经被设备执行，但响应在切换期间丢失。此时软件显示 ConfigurationUncertain，并停止定时发送。不要立即重复写入，应按界面提示分别尝试旧配置、新配置或默认配置重新连接。

## 11. 未知地址查询

> 未知地址查询仅适用于总线上只有一个设备的情况；多设备同时应答会产生总线冲突。

固定请求为 `FE 03 00 00 00 01 + CRC`。成功条件同时包括：

- 响应地址位于 1～64；
- 功能码为 0x03；
- 返回一个寄存器；
- 寄存器值与响应地址一致。

发现地址后只更新本地地址，不会自动发送后续读取。RS-485 总线上存在多个设备时禁止使用该功能。

## 12. 专家寄存器工具

专家工具使用四万区文档地址输入，软件自动换算零基协议地址：`协议地址 = 文档地址 - 40001`。

支持：

- 0x03 连续读取；
- 0x06 写单个原始 16 位字；
- 0x10 写多个原始 16 位字；
- 强制 RawDebug 发送；
- 0xFE 单设备地址查询。

读取结果同时显示 Signed、Unsigned、Hex 和该地址的独立语义解释。地址、波特率代码、布尔值、位掩码和测量值不会套用统一的 int16 规则。

## 13. 通信日志

通信日志按软件 TransactionId 关联 TX、RX、错误和迟到数据。TransactionId 只存在于上位机内部，不存在于 Modbus-RTU 线上。

- 数据缓存最多 5000 条；
- 实时可视列表最多 750 条；
- 可按方向、关键字和 TransactionId 筛选；
- 清空操作不会取消正在执行的事务；
- CSV 导出在线程池执行，使用带 BOM 的 UTF-8，中文不会乱码。

导出时使用调用瞬间的不可变日志快照，通信可以继续进行。

## 14. 超时、迟到响应和重同步

请求超时后，软件不会只依赖“发送前清空串口缓存”。协调器进入 Resynchronizing，并隔离迟到字节。隔离期间禁止新事务和自动重试。

如果请求 A 超时后迟到响应到达，即使它和请求 B 的地址、功能码相同，也只能作为迟到或未请求数据记录，不能完成未来事务。获得完整静默窗口后才允许再次发送；持续噪声超过重同步上限时软件主动断开串口。

Modbus-RTU 没有线上 Transaction ID，因此极端长延迟下仍存在协议固有歧义。软件通过单事务、端口代次、静默隔离、禁止自动重试和内部 TransactionId 降低风险，并在日志中明确保留诊断。

## 15. 常见故障

### 15.1 连接失败

- 检查端口是否被其他程序占用；
- 检查 USB 转串口驱动；
- 检查 9600-8-N-1 是否与设备一致；
- 检查 RS-485 A/B 极性、共地和终端电阻。

### 15.2 一直超时

- 检查从站地址；
- 检查功能码和寄存器范围；
- 检查发送方向控制和收发器接线；
- 适当增加响应总超时；
- 超时后先等待重同步完成，不要连续点击发送。

### 15.3 CRC 错误或原始数据混乱

- 检查波特率、数据位、校验位和停止位；
- 检查线路干扰和接地；
- 检查是否有多个设备同时使用相同地址；
- 使用日志页查看完整 TX/RX 原始十六进制数据。

### 15.4 中文乱码

软件源码、配置和导出日志均使用 UTF-8。用表格软件打开 CSV 时，应选择 UTF-8 编码；软件导出文件已带 BOM，通常可直接识别。

## 16. 安全退出

关闭窗口时，软件会按顺序：

1. 禁止继续交互；
2. 停止定时发送；
3. 以 ApplicationStopping 完成等待中的事务；
4. 等待日志、快照、统计和界面通知排空；
5. 退出唯一接收循环；
6. 关闭并释放串口；
7. 保存安全设置。

退出期间不要强制结束进程，除非应用长时间无响应。

## 17. 发布和完整性

项目发布脚本为 `scripts\publish-win-x64.ps1`。脚本会执行锁定还原、Release 测试、Release 构建、单文件发布、输出目录检查，并显示 EXE 的 SHA256 和字节大小。

自包含隔离验证脚本为 `scripts\verify-self-contained-sandbox.ps1`。它要求 Windows Sandbox 或等效干净 Windows x64 虚拟机，用于证明在没有 .NET 8 Desktop Runtime 的环境中仍能启动并渲染主窗口。
