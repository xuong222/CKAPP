# CH32 工业监控上位机使用说明

## 1. 软件用途

本软件用于通过串口和 Modbus-RTU 协议连接 CH32 多传感器融合检测设备，并提供一套完全独立的普通串口助手。主要功能包括工业仪表盘、报警显示、统一寄存器参数表、原始收发数据、常用指令、手动定时发送、通信日志和 UTF-8/HEX 串口终端。

当前版本支持：

- 0x03：读取保持寄存器；
- 0x06：写单个保持寄存器；
- 0x10：写多个保持寄存器；
- 设备私有 0xFE 未知地址查询；
- Windows x64 自包含单文件发布。

本软件不包含趋势曲线，不会在连接后自动轮询，也不会自动恢复上次定时发送状态。

## 2. 安装和启动

发布包的主程序为 `CKAPP.exe`，发布脚本还会将同一文件复制到工作区根目录，便于直接交付。发布目标是 Windows x64 自包含单文件，设计上不依赖目标电脑预装 .NET Desktop Runtime；正式交付前应使用第 18 节的隔离验证脚本或等效干净虚拟机保存验证证据。

启动步骤：

1. 将 EXE 复制到本地可写目录。
2. 双击运行；首次启动不会自动打开串口。
3. 如果 Windows 显示来源提示，请先核对文件来源和 SHA256，再决定是否运行。
4. 软件设置保存在 `%LOCALAPPDATA%\CH32UpperComputer\settings.json`，内容使用 UTF-8。

建议系统为 64 位 Windows 10 或 Windows 11，屏幕缩放建议为 100%～150%。

## 3. 主界面说明

主窗口由五个页面和顶部 Modbus 状态区组成：

- 实时监控：六张数据卡、综合报警、具体报警、紧凑收发框和单列常用指令；
- 参数设置：40001～40036 统一寄存器表，以及地址、波特率、恢复出厂和 0xFE 专用操作；
- 通信日志：查看、筛选、清空和导出通信记录。
- 固件升级：通过 Ethernet TCP 执行 CH32V317 IAP；
- 串口助手：使用第二套独立串口连接进行 UTF-8/HEX 收发、定时发送和接收视图保存。

六张数据卡依次显示温度、烟雾、PM2.5、CO、CO2 和 SO2。右侧报警区只根据设备返回的 40009、40010 状态显示报警，不会根据测量值自行虚构报警。

## 4. 串口连接

推荐设备参数为：

- 波特率：9600；
- 数据位：8；
- 校验位：None；
- 停止位：One；
- 流控：None；
- 从站地址：1；
- 响应总超时：1000 ms。

操作步骤：

1. 在顶部串口区选择端口和参数。串口列表显示 `USB-SERIAL CH340 (COM7)` 一类友好名称，也允许直接手工输入端口名。
2. 点击“连接”。
3. 连接成功后状态显示“已连接 · 等待手动指令”。
4. 此时软件只启动唯一后台读取循环，不会发送任何读取或写入帧。

软件在启动、展开串口设置、打开下拉框、点击刷新及收到设备插拔通知后异步更新端口列表。当前端口为空、失效或仍为默认 COM1 时，断开状态会优先选择检测到的 WCH/CH340 串口；连接期间只更新列表，不擅自切换活动端口。

连接后没有线路写入属于设计行为。只有点击发送、常用指令、参数操作或手动开启定时发送后才会产生事务。

## 5. 收发框和手动发送

收发框接受十六进制字符，并允许使用空格、Tab、换行或短横线分隔。字符数量必须组成完整字节。

### 5.1 自动 CRC

- 开启“自动 CRC”时，如果输入末尾没有有效 Modbus CRC，软件自动追加 CRC16；
- 如果输入已经包含有效 CRC，软件不会重复追加；
- 关闭“自动 CRC”时，输入会按原始字节发送，适合专家调试。

软件会先严格识别 0x03、0x06、0x10 和固定 0xFE 请求。识别成功时使用标准事务模式；无法识别的帧使用原始调试模式。

### 5.2 标准事务模式

标准事务根据请求结构计算响应长度，并校验 CRC、地址、功能码、数量和写回显。只有完整匹配的成功 0x03 响应可以更新数据卡和寄存器快照。

### 5.3 原始调试模式

原始调试模式保留收到的原始字节。无法推导结构时，以下任一条件会结束一次捕获：

- 字节间静默超时；
- 总响应超时；
- 4096 字节接收上限。

原始捕获不会更新设备参数或数据卡。

## 6. 常用指令

监控页右侧提供五条单列常用指令：

1. 读取监测数据：40003～40010；
2. 读取全部寄存器：40001～40036；
3. 读取报警参数：40011～40023；
4. 读取补偿参数：40030～40035；
5. 未知地址查询：固定 0xFE 查询。

点击常用指令会按当前从站地址重新生成完整帧、显示到输入框并立即发送，不需要再点击一次“发送”。事务进行期间所有常用指令按钮会进入忙状态，快速重复点击不会排队。

## 7. 定时发送

定时发送默认关闭，连接后也不会自动启动。

启动步骤：

1. 准备并检查当前收发框指令；
2. 设置定时间隔，允许范围为 100～3,600,000 ms；
3. 点击“开启定时”；
4. 软件先等待一个完整间隔，再尝试第一次发送。

定时策略是固定延迟：一次事务完全结束后，才重新等待一个完整间隔。不会积累 tick、不会追赶补发，也没有请求队列。

点击“停止定时”会立即取消下一次调度。已经进入物理写入的单次事务允许完成，但完成后不会安排下一次。断开串口、修改地址、修改波特率、恢复出厂、超时重同步或退出程序都会保持定时发送关闭，必须由用户再次手动开启。

## 8. Busy 背压

同一时刻最多允许一个活动 Modbus 事务。当前事务尚未完成时：

- 发送、常用指令和参数操作按钮进入忙状态；
- 快速重复点击不会建立队列；
- 穿透到协调器的第二项请求立即返回 Busy；
- Busy 请求不分配 TransactionId，也不会写串口。

界面提示“当前已有请求等待处理，请完成或取消后再试。”时，请等待当前事务结束或断开连接。

## 9. 参数页面

进入参数页不会自动读取。页面统一列出 40001～40036，每行显示选择框、地址、名称、权限、解析当前值、Signed/Unsigned/Hex 原始值、单位、待写值、校验状态和行操作。点击寄存器名称会选择该行并定位待写输入；只读项不可编辑。

读取操作：

- `读取全部`：使用一帧 0x03 读取 40001～40036；
- 行内 `读取`：读取单个寄存器；
- `读取选中`：按所选最小至最大地址构建一帧 0x03，并更新响应范围内全部当前值；
- 实时监控中的任意成功 0x03 常用指令也会更新同一份设备快照、仪表盘和参数表。

普通可写寄存器分为两个连续组：

- 40011～40023：报警阈值、回差和报警使能；
- 40030～40035：六项补偿参数。

普通寄存器的行内 `修改` 使用 0x06。`修改选中` 只允许选择同一普通可写组：连续选择直接使用一帧 0x10；非连续选择会先独占通信序列，使用 0x03 回读首尾跨度并合并未修改项，再发送一帧 0x10。回读失败、输入无效、包含只读或特殊项、跨组选择时均不发送写帧；回读和写入之间也不允许手动、常用或定时请求插入。

40023 可以使用 `0x0000`～`0x003F` 原始掩码，也可以使用六个逐项开关。只允许低六位。

40001、40002 和 40036 显示“专用流程”。从站地址、波特率和恢复出厂不会混入普通 0x10 参数组，必须使用各自的安全流程。地址、波特率代码、报警掩码和测量值继续由各自的寄存器定义解释，不采用全局 int16 规则。

## 10. 地址、波特率和恢复出厂

### 10.1 修改地址

软件使用旧地址发送 0x06，并验证完整回显。只有收到旧地址下的正确响应后，才更新本地从站地址。允许地址范围为 1～64。

### 10.2 修改波特率

软件在旧波特率下写入 40002，收到正确回显后关闭串口，再按新波特率重新打开。支持代码：

- 0：2400；
- 1：4800；
- 2：9600；
- 3：19200；
- 4：38400；
- 5：57600。

### 10.3 恢复出厂

勾选二次确认后，软件写入 40036=1。成功后本地配置切换到地址 1、9600-8-N-1。40036 读取恒为 0，命令不会作为持久状态保留。

### 10.4 ConfigurationUncertain

地址、波特率或恢复出厂写入可能已经被设备执行，但响应在切换期间丢失。此时软件显示 ConfigurationUncertain，并停止定时发送。不要立即重复写入，应按界面提示分别尝试旧配置、新配置或默认配置重新连接。

## 11. 未知地址查询

> 未知地址查询仅适用于总线上只有一个设备的情况；多设备同时应答会产生总线冲突。

固定请求为 `FE 03 00 00 00 01 + CRC`。成功条件同时包括：

- 响应地址位于 1～64；
- 功能码为 0x03；
- 返回一个寄存器；
- 寄存器值与响应地址一致。

发现地址后只更新本地地址，不会自动发送后续读取。RS-485 总线上存在多个设备时禁止使用该功能。

## 12. 通信日志

通信日志按软件 TransactionId 关联 TX、RX、错误和迟到数据。TransactionId 只存在于上位机内部，不存在于 Modbus-RTU 线上。

- 数据缓存最多 5000 条；
- 实时可视列表最多 750 条；
- 可按方向、关键字和 TransactionId 筛选；
- 清空操作不会取消正在执行的事务；
- CSV 导出在线程池执行，使用带 BOM 的 UTF-8，中文不会乱码。

导出时使用调用瞬间的不可变日志快照，通信可以继续进行。

## 13. 超时、迟到响应和重同步

请求超时后，软件不会只依赖“发送前清空串口缓存”。协调器进入 Resynchronizing，并隔离迟到字节。隔离期间禁止新事务和自动重试。

如果请求 A 超时后迟到响应到达，即使它和请求 B 的地址、功能码相同，也只能作为迟到或未请求数据记录，不能完成未来事务。获得完整静默窗口后才允许再次发送；持续噪声超过重同步上限时软件主动断开串口。

Modbus-RTU 没有线上 Transaction ID，因此极端长延迟下仍存在协议固有歧义。软件通过单事务、端口代次、静默隔离、禁止自动重试和内部 TransactionId 降低风险，并在日志中明确保留诊断。

## 14. 常见故障

### 14.1 连接失败

- 点击刷新并确认列表中显示正确的 USB 转串口友好名称；若枚举失败，可手工输入端口；
- 检查端口是否被其他程序占用；
- 检查 USB 转串口驱动；
- 检查 9600-8-N-1 是否与设备一致；
- 检查 RS-485 A/B 极性、共地和终端电阻。

### 14.2 一直超时

- 检查从站地址；
- 检查功能码和寄存器范围；
- 检查发送方向控制和收发器接线；
- 适当增加响应总超时；
- 超时后先等待重同步完成，不要连续点击发送。

### 14.3 CRC 错误或原始数据混乱

- 检查波特率、数据位、校验位和停止位；
- 检查线路干扰和接地；
- 检查是否有多个设备同时使用相同地址；
- 使用日志页查看完整 TX/RX 原始十六进制数据。

### 14.4 中文乱码

软件源码、配置和导出日志均使用 UTF-8。用表格软件打开 CSV 时，应选择 UTF-8 编码；软件导出文件已带 BOM，通常可直接识别。

## 15. 安全断开和退出

断开串口会立即使会话失效并取消等待事务。可能阻塞的驱动 `Close/Dispose` 在后台执行，前台最多等待 750 ms；若仍未结束，界面显示“已断开，串口驱动仍在释放”，释放完成前禁止立即重开，但界面不会冻结。

关闭窗口时软件会立即隐藏窗口，并在后台幂等执行：

1. 禁止继续交互；
2. 停止串口助手定时发送，断开助手并等待其独立接收循环退出；
3. 停止 Modbus 定时发送；
4. 以 ApplicationStopping 完成等待中的事务；
5. 尽力保存日志和安全设置；
6. 取消 Modbus 接收循环并关闭串口。

整体退出等待上限为 2 秒，超时后结束 WPF 生命周期，未完成的驱动释放继续由后台线程收尾。重复关闭不会启动第二套清理流程。

## 16. 固件升级

“固件升级”页通过以太网 TCP 向 CH32V317 Bootloader 下载原始 `.bin`：

1. 选择 1～204800 字节的 `.bin` 文件，核对文件名、大小和整体 CRC32；
2. 设置 Bootloader IPv4 地址和 TCP 端口；
3. 勾选“确认该固件按 `0x0800C000` 链接生成”后开始升级；
4. 等待 HELLO、BEGIN、DATA、END 和 END 后二次 HELLO 完成；
5. 页面显示“升级成功”后，按需点击“运行 App”。

裸 `.bin` 本身不包含可验证的链接地址信息，因此确认框只表示操作者已核对固件来源，不表示软件从文件中证明了链接地址。

升级期间软件会停止定时发送并暂停新的 Modbus 数据操作，但不会自动关闭已经打开的串口；升级结束后也不会自动恢复定时发送。刷新串口和手动断开仍可使用。

每条 TCP 连接的 sequence 均从 1 开始。BEGIN、全部 DATA 和 END 必须位于同一连接；传输中断后不续传旧 offset。END 后优先在原连接发送 HELLO，原连接断开时只新建验证连接，不会未经验证直接再次擦除 App。

RUN 结果与升级结果分开显示：

- “已确认启动”：收到了完整匹配的 RUN ACK；
- “启动结果不确定”：RUN 可能已经送达，但完整 ACK 前发生超时或断线；已经确认的升级成功不会因此改判失败；
- “启动被拒绝”：设备返回了明确匹配的 RUN NACK。

IAP 日志与 Modbus 日志相互独立，缓存最多 5000 条、页面最多显示 750 条。DATA 默认只显示头部摘要；只有诊断需要时才启用“显示完整 DATA 载荷”。CSV 使用带 BOM 的 UTF-8 并在线程池生成。

关闭窗口时如果完整升级正在进行，软件会要求确认；确认后窗口立即隐藏，取消事务并断开 TCP。若请求已经进入响应等待且线路可能残留旧响应，软件会优先废弃该连接，而不会在同一字节流中把旧响应误认为 ABORT 响应。

## 17. 串口助手

“串口助手”是第 5 个标签页，使用第二个 `SerialPortTransport` 和自己唯一的接收循环，不经过 Modbus 事务协调器、CRC、响应超时或 Ethernet IAP 互斥门。因此它可以和 Modbus、Ethernet IAP 同时工作，但必须选择不同的物理 COM 口。

### 17.1 连接和端口冲突

- 支持 `2400/4800/9600/19200/38400/57600/115200`，默认 `COM1、115200-8-N-1`；
- Modbus 与助手使用同一个大小写不敏感的端口占用登记器。若一处已经打开 `COM7`，另一处不能用 `com7` 重复打开；
- 租约保持到驱动的物理句柄完全释放。界面已经显示断开但后台驱动仍在清理时，同一 COM 口仍会被拒绝；
- 外部程序占用、设备拔出和驱动 I/O 异常会显示独立中文错误，不会主动断开另一套串口会话。

### 17.2 UTF-8 与 HEX 收发

- 发送和接收可分别选择 UTF-8 或 HEX；HEX 只接受完整字节，不会追加 Modbus CRC；
- UTF-8 发送使用严格编码，无效代理项会被拒绝；接收使用跨批次 Decoder，多字节字符跨底层读取边界时不会被截断，非法序列显示替代字符；
- 单次负载上限为 64 KiB；
- “发送新行”在两种发送模式下都在负载末尾追加 `0D 0A`（CRLF），含义遵循[正点原子 XCOM 使用说明](https://wiki.alientek.com/docs/Boards/STM32/DNN647/basic-examples/serial/)；
- 接收区只显示 RX，本软件发送的 TX 不会回显到接收区。

### 17.3 接收缓存、暂停和统计

接收数据按最多 4096 字节或 50 ms 合并显示，并保留在 512 KiB 有界原始缓存中。缓存满后淘汰最旧完整批次并累加“丢弃”字节；切换 UTF-8/HEX 或时间戳时从原始缓存重新渲染。

点击“暂停 / 恢复”后，软件仍持续排空串口并累计 RX 字节，但暂停期间的新数据不会保存或补显示，同时计入“暂停丢弃”。恢复后只显示恢复时刻以后到达的新数据。点击“清空接收”会同时清除当前视图、原始缓存以及 TX 次数、TX 字节、RX 字节和全部丢弃计数。

### 17.4 定时发送和保存

启动定时发送时会冻结当时的模式、输入和 CRLF 结果；先等待一个完整间隔，写完一帧后才重新等待下一周期。不会并发写入、排队或追赶补发。运行期间手动发送、输入内容、发送模式和“发送新行”均锁定；停止、断开或退出后不再开始新的写入。

“保存当前视图”保存的是按钮按下时实际显示的文本，因此包括当前 UTF-8/HEX 模式、时间戳和换行效果；文件使用带 BOM 的 UTF-8 `.txt`。线路参数、收发模式、“发送新行”、时间戳、自动滚动、间隔、保存目录和最后输入会在重启后恢复；连接、暂停和定时发送运行状态永远不会恢复为开启。

## 18. 发布和完整性

项目发布脚本为 `scripts\publish-win-x64.ps1`。脚本会执行锁定还原、Release 测试、Release 构建、单文件发布、输出目录检查，并显示 EXE 的 SHA256 和字节大小。

自包含隔离验证脚本为 `scripts\verify-self-contained-sandbox.ps1`。它要求 Windows Sandbox 或等效干净 Windows x64 虚拟机，用于证明在没有 .NET 8 Desktop Runtime 的环境中仍能启动并渲染主窗口。
