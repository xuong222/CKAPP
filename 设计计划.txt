1. 项目目标
-------------------------------------------------------------------------------

1.1 核心目标

在 D:\CH32\SHANGWEJI 中开发一款面向当前 CH32 多传感器固件的 Windows 桌面上位机。
应用通过串口使用 Modbus-RTU 协议与设备通信，提供以下能力：

1. 显示温度、烟雾、PM2.5、CO、CO2、SO2 六项参数数值。
2. 显示综合报警状态，并明确指出发生报警的具体传感器。
3. 读取和写入 40001～40036 寄存器范围内允许操作的参数。
4. 配置串口、波特率、数据位、校验位、停止位、从站地址和响应超时。
5. 提供 Codex 对话框风格的数据收发区，显示完整 TX/RX 原始帧。
6. 支持手动发送十六进制指令、自动追加 CRC、保存常用指令及一键发送。
7. 支持由用户手动开启和停止的定时发送；连接后默认不自动轮询。
8. 提供清晰的异常提示、通信统计、日志筛选、清空和 UTF-8 导出。
9. 发布为 Windows x64 自包含单文件 EXE，可直接双击运行。

1.2 成功标准

1. 无设备时，应用可正常启动、浏览界面、编辑配置，不崩溃。
2. 连接串口后，应用停留在“等待手动指令”状态，不自动发送任何数据。
3. 用户手动发送合法读指令后，原始收发区显示 TX/RX，相关数据卡片正确更新。
4. 用户手动开启定时发送后，应用按指定间隔串行发送当前指令；停止后不再发送。
5. CRC 错误、超时、串口拔出、Modbus 异常响应等情况均有可理解的中文提示。
6. 每一项可写参数均经过客户端范围校验；禁止对只读寄存器执行参数页写入。
7. 中文界面、中文路径、中文日志、中文配置内容均无乱码。
8. 自动化测试、Debug 构建、Release 构建和 win-x64 单文件发布均成功。
9. 最终 EXE 在未安装 .NET 运行时的 Windows x64 环境中可启动。

1.3 非目标（本期不实现）

1. 不修改 D:\CH32\MQTT_UART 中的固件代码。
2. 不实现 Modbus TCP、MQTT、云平台、数据库、用户登录和远程升级。
3. 不添加传感器趋势曲线；该功能已由用户明确取消。
4. 不在连接后默认自动读取；所有自动发送功能必须由用户手动开启。
5. 不实现固件未定义的写操作，不绕过设备寄存器范围限制。
6. 不将“接近阈值”伪装为设备报警；正式报警状态以 40010 位定义为准。

2.2 已识别差异及决策

1. 旧点表写明设备支持 0x03、0x06；当前固件还实现了 0x10。
   决策：上位机支持 0x03、0x06、0x10，以当前固件为准。
2. 旧规约中的未知地址查询示例使用起始地址 0x0100；当前固件仅接受
   [FE][03][00][00][00][01][CRC]。
   决策：内置“查询未知地址”严格使用当前固件定义的 0x0000 起始地址。
3. 点表对报警回差范围的文字与负默认值存在冲突；当前固件明确规定回差不得为正。
   决策：客户端校验以固件 AppAlarm_IsWritableValueValid() 为准，回差只允许 <= 0。
4. 点表写过地址可能断电重启生效；当前固件实现为应答发送完成后切换。
   决策：上位机等待旧参数下的写应答完成，再更新本地地址或波特率。

3. 协议设计
-------------------------------------------------------------------------------

3.1 串口默认值

port = 用户选择
baud_rate = 9600
data_bits = 8
parity = None
stop_bits = One
handshake = None
slave_address = 1
response_timeout_ms = 1000
write_timeout_ms = 1000
periodic_interval_ms = 1000
automatic_send_on_connect = false

串口界面允许用户调整端口、波特率、数据位、校验位、停止位和超时；针对本设备明确提示
推荐值为 9600-8-N-1。波特率下拉至少包含 2400、4800、9600、19200、38400、57600。

3.2 Modbus-RTU 编码规则

1. CRC16 初值 0xFFFF，多项式 0xA001，帧内低字节在前、高字节在后。
2. 寄存器数据按 Modbus 大端顺序传输：高字节在前、低字节在后。
3. 寄存器值按 16 位有符号整数解释；位掩码场景按 ushort 解释。
4. 文档编号 40001 对应协议地址 0x0000；协议地址 = 文档编号 - 40001。
5. 支持功能码：
   - 0x03：读保持寄存器。
   - 0x06：写单个保持寄存器。
   - 0x10：写多个保持寄存器。
6. 支持设备私有未知地址查询：FE 03 00 00 00 01 + CRC。
7. 识别标准异常帧：功能码最高位置 1，异常码显示为中文含义。
8. 0xFE 查询是地址匹配的明确例外：请求地址为 0xFE，但设备使用真实从站地址应答。
   只有当响应地址位于 1～64、功能码为 0x03、返回一个寄存器且寄存器值与响应地址一致时，
   才判定发现地址成功；成功后将发现的真实地址填入连接设置，但不自动发送后续请求。

3.3 请求生命周期

状态序列：
Disconnected -> ConnectedIdle -> Sending -> WaitingResponse -> Completed/Failed -> ConnectedIdle

规则：
1. 连接成功后进入 ConnectedIdle，不创建自动轮询任务。
2. 手动发送、常用指令和定时发送均提交到同一个事务协调器。
3. 同一时刻最多存在一个正在等待响应的 Modbus 事务。
4. 每次事务在发送前清理仅属于上一事务的残留接收状态，但不丢弃已记录日志。
5. 根据请求功能码、从站地址和数量推导预期响应长度；收到完整帧后立即校验。
   普通请求要求响应地址与请求地址相同；0xFE 查询按 3.2 第 8 条执行专用匹配。
6. 超时后事务失败，记录超时，但串口保持可用；连续失败不自动无限重试。
7. 手动指令可在定时模式下优先插队；手动事务完成后，定时计划继续。
8. 停止定时发送后取消未来计划，不强行中断已经开始的单次事务。
9. 断开串口时取消等待中的事务与定时计划，并释放串口句柄。

3.4 指令输入规则

1. 输入框接受大小写十六进制字符以及空格、Tab、换行、短横线分隔符。
2. 清理分隔符后必须为偶数个十六进制字符，否则禁止发送并显示原因。
3. “自动 CRC”开启时：
   - 用户输入请求主体，上位机计算并追加 CRC。
   - 若用户输入看似已包含正确 CRC，界面提示并避免重复追加。
4. “自动 CRC”关闭时：按用户输入原样发送，但仍在日志中注明是否通过 CRC 检查。
5. 定时发送只能在串口已连接、输入合法、间隔合法时启动。
6. 定时间隔使用正整数毫秒；初始建议范围 100～3,600,000 ms。

3.5 响应更新规则

1. 数据卡片初始显示“--”。
2. 仅当响应完成 CRC、地址、功能码、长度和字节数校验后，才更新寄存器缓存。
3. 读 40003～40008 的响应更新对应数据卡片。
4. 读 40009 更新综合报警继电器状态。
5. 读 40010 更新六项报警位，并在右侧报警栏列出具体报警项。
6. 读 40023 更新六项报警使能状态。
7. 部分区间读取只更新响应实际覆盖的寄存器，不清空其他已有值。
8. 错误响应不得覆盖最后一次有效数值；卡片显示最后更新时间并标记通信错误。
9. 0xFE 查询成功时仅更新“已发现从站地址”和 40001 缓存；不得把 0xFE 当作真实设备地址。

5. 界面设计（以用户确认的第五版为唯一实现基准）
-------------------------------------------------------------------------------

5.1 总体布局

1. 单主窗口，建议初始尺寸 1360x820，最小尺寸 1100x700。
2. 左侧固定导航：实时监控、参数设置、寄存器工具、通信日志、系统信息。
3. 顶部状态栏：串口、波特率、从站地址、连接状态、最后响应耗时。
4. 深墨蓝背景、青绿色主强调色、红色报警色、琥珀色注意色。
5. 字体优先使用 Microsoft YaHei UI / Segoe UI，避免中文乱码和字形缺失。

5.2 实时监控页

1. 左上区域使用两行三列数据卡片；卡片比第四版稍小。
2. “温度 40003”等卡片标题使用更大字号和更高对比度。
3. 卡片显示：名称、文档寄存器地址、格式化值、单位、正常/报警状态、更新时间。
4. 卡片右侧为报警信息栏：
   - 综合报警继电器状态。
   - 当前报警数量。
   - 温度、烟雾、PM2.5、CO、CO2、SO2 六项逐条状态。
   - 发生报警时明确显示具体项目，使用红色而非仅依赖颜色的小图标。
5. 下方左侧为数据收发消息流；上边界使用低对比度 1px 细分隔线。
6. 消息流表现类似 Codex 对话：TX 右对齐、RX 左对齐、系统校验结果居中。
7. 消息输入框固定在消息流底部，与收发框合并，不单独占用大型指令面板。
8. 输入栏附带自动 CRC、保存为常用、定时发送开关、间隔和发送统计。
9. 下方右侧为单列常用指令列表。

5.3 参数设置页

分组：通信参数、报警阈值、报警回差、报警使能、传感器补偿、危险操作。

规则：
1. “读取当前参数”由用户手动触发。
2. 输入控件展示单位、允许范围和寄存器编号。
3. 单项保存使用 0x06。
4. 连续区间批量保存可使用 0x10；提交前先完整预校验，避免部分写入。
5. 地址/波特率写入后执行特殊切换流程并给出明确提示。
6. 恢复出厂位于危险操作区，必须二次确认并说明将恢复哪些参数。

5.4 寄存器工具页

1. 自定义从站地址、功能码、起始地址、数量和值。
2. 同时显示文档地址和零基协议地址，避免 40001/0x0000 混淆。
3. 支持 0x03、0x06、0x10 请求构建和原始帧预览。
4. 提供有符号十进制、无符号十进制、十六进制三种显示。
5. 只读寄存器在参数化写入界面禁用；原始帧模式仍允许专家自行输入，但显示风险提示。

5.5 通信日志页

1. 按全部、TX、RX、错误筛选。
2. 显示时间戳、方向、原始十六进制、解析摘要、CRC、响应耗时和错误原因。
3. 支持清空和导出；导出使用 UTF-8 with BOM，便于 Windows 记事本直接查看中文。
4. UI 日志使用有界集合，默认最多保留 5000 条，防止长时间运行耗尽内存。

5.6 系统信息页

显示应用版本、.NET 版本、操作系统、配置文件路径、日志导出目录、协议支持范围、
寄存器点表版本和免责声明。不得展示或收集无关隐私数据。

6.2 依赖方向

App -> Infrastructure -> Core
App -> Core
Core -> 无项目依赖
Tests -> 被测项目

禁止反向依赖；Core 不得引用 PresentationFramework、System.IO.Ports 或具体文件系统实现。

6.3 关键组件

1. ModbusCrc16：CRC 计算与验证。
2. ModbusRequestFactory：构建 0x03/0x06/0x10/0xFE 请求。
3. ModbusResponseParser：解析正常响应和异常响应，返回结构化结果。
4. DeviceRegisterMap：定义 36 个寄存器的权限、名称、单位、缩放和范围。
5. DeviceSnapshot：保存最后一次有效寄存器缓存和更新时间。
6. SerialPortTransport：异步打开、关闭、写入和接收串口数据。
7. ModbusTransactionCoordinator：确保请求串行化，管理超时、取消和响应匹配。
8. PeriodicSendService：仅在用户手动开启后调度重复发送。
9. SettingsStore：保存非敏感 UI/串口偏好到 UTF-8 JSON。
10. CommunicationLogService：生成有界日志集合并导出 UTF-8 文本。
11. MainWindowViewModel：导航、连接状态和跨页面共享状态。

6.4 线程规则

1. 串口读取、超时等待、文件导出不得阻塞 WPF UI 线程。
2. ViewModel 更新 ObservableCollection 或绑定属性时切回 Dispatcher。
3. 串口生命周期使用异步锁或 SemaphoreSlim 防止重复打开/关闭。
4. Modbus 事务协调器保证一次一个请求，禁止多个页面直接并发写 SerialPort。
5. 定时发送使用 CancellationToken；窗口关闭时必须取消并等待后台任务结束。
6. 不使用 Thread.Abort，不使用无限阻塞 Read，不吞掉后台异常。

-------------------------------------------------------------------------------
7. 异常处理与用户反馈
-------------------------------------------------------------------------------

异常类型 -> UI 行为：

1. 端口不存在：阻止连接，提示刷新端口列表。
2. 端口被占用/拒绝访问：保持断开状态，显示端口名称和系统错误摘要。
3. 串口意外拔出：取消事务和定时发送，切换为断开状态，保留日志。
4. 请求超时：记录 TX + 超时系统消息，不修改最后有效数据。
5. CRC 错误：记录完整 RX、期望 CRC 与实际 CRC，不更新寄存器。
6. 地址不匹配：记录为不匹配响应，不当作成功。
7. 功能码不匹配：记录期望与实际功能码，不更新寄存器。
8. 异常响应：显示异常码 0x01/0x02/0x03/0x04 及中文含义。
9. 帧长度/字节数错误：保存原始帧并显示解析失败原因。
10. 参数越界：在发送前阻止写入，并定位具体字段。
11. 配置文件损坏：备份或忽略损坏配置，以默认值启动并提示一次。
12. 日志导出失败：不丢失内存日志，显示目标路径和错误摘要。

错误消息不得只显示“失败”；必须包含操作、对象和可行动的恢复建议。

8. 本地配置与数据安全
-------------------------------------------------------------------------------

1. 配置路径：%LocalAppData%\CH32UpperComputer\settings.json。
2. 保存内容：窗口大小、最后选择的串口设置、超时、从站地址、自动 CRC 偏好、
   定时间隔、用户自定义常用指令。
3. 不保存“定时发送已开启”状态；应用每次启动和每次连接后均默认为关闭。
4. 不自动保存或恢复危险操作确认状态。
5. JSON 使用 UTF-8，写入采用临时文件 + 原子替换，降低断电损坏风险。
6. 不收集网络数据，不上传日志，不保存凭据。

9. 测试策略（强制测试先行）
-------------------------------------------------------------------------------

9.1 TDD 规则

1. 每个生产函数在实现前先编写一个会因功能缺失而失败的测试。
2. 必须实际运行测试并确认失败原因正确，再写最小实现。
3. 实现后运行目标测试和完整测试集。
4. 发现缺陷时先添加可复现缺陷的失败测试，再修复。
5. UI 视觉代码无法完全单元测试时，业务逻辑移入 ViewModel/Service 测试，XAML 进行构建和截图验证。

9.2 Core 测试矩阵

1. CRC 官方/固件已知向量。
2. 0x03、0x06、0x10 和 0xFE 请求帧构建。
   0xFE 测试必须覆盖“请求 0xFE、响应真实地址、寄存器值与真实地址一致”的专用匹配。
3. 正常读响应、单写回显、多写回显解析。
4. 异常响应 0x01/0x02/0x03/0x04。
5. CRC 错误、短帧、超长帧、错误字节数、错误地址、错误功能码。
6. 40001 <-> 0x0000 地址转换及边界 40036 <-> 0x0023。
7. int16/ushort 转换、负数回差、温度/CO/SO2 缩放，以及烟雾 MQ2 线性单位不做 ppm 换算。
8. 全部可写寄存器的最小值、最大值、越界值和只读拒绝。
9. 报警位和报警使能位解析。

9.3 Infrastructure 测试矩阵

1. 连接后不自动写出任何字节。
2. 手动发送产生一次事务。
3. 定时发送只有手动启动后才产生事务。
4. 停止定时发送后不再创建新事务。
5. 手动事务在定时模式下优先执行且无并发写。
6. 超时、取消、串口关闭、错误响应均能释放事务锁。
7. 地址/波特率写应答完成后才更新本地通信设置。
8. 日志有界、筛选正确、UTF-8 导出中文无乱码。
9. 配置缺失、合法、损坏三种加载路径。

9.4 构建与人工验收

1. dotnet test：全部测试 0 失败。
2. dotnet build -c Release：0 错误；项目自有代码尽量 0 警告。
3. dotnet publish win-x64：生成单文件 EXE。
4. 启动烟雾测试：EXE 启动后主窗口可见且无未处理异常。
5. UI 截图检查：第五版布局、卡片比例、标题字号、报警栏、细上边界、单列常用指令。
6. 中文检查：窗口标题、数据卡片、错误提示、配置和导出日志无乱码。
7. 硬件验收（需要真实设备）：03 读取、06 写入、10 批量写、FE 查询、地址/波特率切换。

12. 需在实施期间保持的关键不变量
-------------------------------------------------------------------------------

INVARIANT-01：未由用户手动触发时，不得向串口发送数据。
INVARIANT-02：任何时刻最多一个 Modbus 请求等待响应。
INVARIANT-03：CRC/地址/功能码/长度校验失败的响应不得更新数据卡和寄存器缓存。
INVARIANT-04：参数页不得写入只读寄存器或越界值。
INVARIANT-05：地址/波特率只在旧通信参数下的写应答完整结束后切换。
INVARIANT-06：停止定时发送或断开串口后不得产生新的定时请求。
INVARIANT-07：正式报警状态只来自 40009/40010，不凭空制造设备报警。
INVARIANT-08：应用退出前必须取消后台任务并释放串口。
INVARIANT-09：所有持久化文本与导出日志使用 UTF-8。
INVARIANT-10：不得修改 D:\CH32\MQTT_UART 固件源码。
